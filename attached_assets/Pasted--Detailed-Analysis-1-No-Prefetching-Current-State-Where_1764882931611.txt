📊 Detailed Analysis
1️⃣ No Prefetching - Current State
Where it is now:

home_operation.js - Auto-plays first favorite/featured but doesn't prefetch adjacent items
channel_operation.js - Loads streams only when channel is focused (visible lag when zapping)
vod_series_player.js - Starts current item only, no next episode prefetch
Problem:
When user switches channels or goes to next episode, there's a visible loading delay because stream URL isn't ready.

Recommended Solution:

┌─────────────────────────────────────────────────────────┐
│  PREFETCH STRATEGY                                      │
├─────────────────────────────────────────────────────────┤
│  Live Channels:                                         │
│  • When channel focused → prefetch next/prev channel    │
│  • Keep 2-3 URLs in memory (LRU cache)                 │
│  • Cancel on navigation change                          │
├─────────────────────────────────────────────────────────┤
│  VOD/Series:                                            │
│  • At 80% playback → prefetch next episode             │
│  • On episode hover → prefetch metadata                │
│  • Preload HLS manifest + first segment                │
├─────────────────────────────────────────────────────────┤
│  Home Preview:                                          │
│  • When slider focus changes → prefetch selected item  │
│  • Cap memory to avoid growth                          │
└─────────────────────────────────────────────────────────┘

2️⃣ Reconnect Logic Scattered - Current State
Where it is now:

File	What it does
player.js	AVPlay init/play, reconnect counters, timers
channel_operation.js	UI locks, display area scheduling, close/reinit player
vod_series_player.js	Similar UI locks, display area, player management
Problem:
No single service handles stall detection, retry/backoff, or resume. Each screen manages its own logic = bugs, inconsistency.

Recommended Solution - Create playerService:

┌─────────────────────────────────────────────────────────┐
│  UNIFIED PLAYER SERVICE                                 │
├─────────────────────────────────────────────────────────┤
│  playerService.play(url, context)                       │
│    ├── Stall/Error detection (AVPlay buffering events) │
│    ├── Auto-retry with backoff (3 tries: 1s/2s/4s)     │
│    ├── UI callbacks (show/hide loader, toast)          │
│    └── Resume-time persistence                         │
├─────────────────────────────────────────────────────────┤
│  BEFORE: channel_operation.js manages own timers       │
│  AFTER:  channel_operation.js calls playerService.play │
├─────────────────────────────────────────────────────────┤
│  Benefits:                                              │
│  • Single place for retry logic                        │
│  • Consistent error handling                           │
│  • Easier debugging                                    │
└─────────────────────────────────────────────────────────┘

3️⃣ Search Slow with 1000+ Items - Current State
Where it is now:

search_page.js - Filters all categories in-memory, renders in chunks of 50
Still creates full DOM nodes and images for all results
No virtualization
Problem:
Large result sets (1000+ channels/movies) cause UI jank and freezing because all DOM elements are created.

Recommended Solution - Virtualization:

┌─────────────────────────────────────────────────────────┐
│  VIRTUALIZED SEARCH                                     │
├─────────────────────────────────────────────────────────┤
│  BEFORE:                                                │
│  [Create 1000 DOM nodes] → Slow, janky                 │
│                                                         │
│  AFTER:                                                 │
│  [Create only 60 visible nodes] → Fast, smooth         │
│  • Recycle DOM nodes on scroll                         │
│  • Lazy-load images only when visible                  │
│  • Use document fragments                              │
├─────────────────────────────────────────────────────────┤
│  Implementation:                                        │
│  1. Keep full filtered array in memory                 │
│  2. Render only viewport window (60 items)             │
│  3. On scroll/navigation → update visible items        │
│  4. Reuse DOM nodes instead of creating new            │
│  5. data-src for images → load when entering viewport  │
└─────────────────────────────────────────────────────────┘
